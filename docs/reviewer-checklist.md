# Reviewer Walkthrough Checklist

A short, opinionated checklist for reviewing pull requests. Work through it in order — every item earns a moment of your attention before you form a verdict.

1. Read the pull request description before opening the diff, so the author's stated intent frames what you are about to see.
2. Run the checks you would expect the author to have run — build, tests, linters — before you comment on anything.
3. Read the entire diff once, top to bottom, before you start typing, so your early notes do not contradict what you learn later in the file.
4. Leave comments inline on the exact lines they concern, never as a single wall of text at the top of the review.
5. Respond to the author's own inline notes, especially where they flagged uncertainty or asked for a second opinion.
6. Finish with an explicit approval or an explicit request for changes — never leave a review hanging in the middle ground.
